## Found and fixed on the way (all in `kestrel-gorm-dynamodb`, each with a spec; 23 pass)

1. **Changed entities were not written without `save()`.** Hibernate writes them at flush, and
   Rundeck relies on that. For example, job delete detaches its executions with
   `exec.scheduledExecution = null`. Now:
   - the session keeps each entity's loaded state and writes the ones that changed;
   - inside a Hibernate transaction, GORM calls share one session, flushed before commit;
   - `withTransaction` joins that session.
2. **Cascades wrote to the parent's table.** GORM calls a persister with the associated entity.
   Deleting a job with options therefore deleted **other jobs whose ids equalled the option ids**
   and left the options behind. Execution deletes removed unrelated workflows the same way. Entry
   operations now go to the persister of the entity they are called with.
3. **Deleted items came back.** A workflow deleted through a lazy proxy was written back after its
   delete. Now:
   - deletions are tracked by entity and id;
   - updates to deleted items are dropped;
   - every update is conditional on the item existing, so one deleted by another pod fails like a
     version conflict, and the conflict logs the item.
4. **`this.` in an EXISTS nested in association criteria pointed at the wrong row.** In
   `ExecutionQuery`'s job-reference filter, `this.` resolved to the associated job instead of the
   root execution. It matched only when a job id equalled an execution id, so it passed on fresh
   installs and failed later.
5. **The first writes on a fresh install created tables one at a time inside the request.** The
   first job import timed out after 60 s. All tables are now created in parallel at startup;
   21 tables were created before the pods went ready.

Still not done in M2c:
- **Sorted indexes for large execution and report tables.** Lists filter in memory over
  index-narrowed candidates; this is fine at reference scale.
- **The upstream API functional suite.** It is ADR 0004's exit criterion and is planned for M2d.
